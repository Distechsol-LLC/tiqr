TiQR: installing

Linux (needs root):    sudo ./install.sh
Windows (needs admin): run tiqr_setup.exe

Linux: the script copies the program to /opt/tiqr and the settings and data to /var/lib/tiqr, which
upgrades leave alone. Then it asks for the address operators' PCs will use, the port, and the first admin
account. It opens the port in the firewall and installs TiQR as a service that starts at boot. Edit
tiqr_brand.jsonc before installing if you need your own name, logo or languages.

Windows: tiqr_setup.exe asks for the same settings in a wizard, writes tiqr_brand.jsonc and the logo to
C:\ProgramData\TiQR, copies the program to C:\Program Files\TiQR, then runs tiqr install with the address and
port from the wizard. That run stays in a terminal window: it asks for the first admin account, prints the
REQUEST CODE (again later: tiqr license request-code) and opens the browser at the chosen port.

Branding changes take effect on restart: edit tiqr_brand.jsonc in the data folder, then restart the service.

Activating the license
----------------------
TiQR refuses all work until it has a license. At the end of the install it prints a REQUEST CODE.
1. Send that code to your vendor. (Again later: tiqr license request-code.)
2. Open the address it printed in a browser, sign in as the admin, and paste the key the vendor
   sends back into the License page.
   Without a browser: tiqr license activate --as <admin> <key>   (or --file key.txt)
   Check it with: tiqr license status

A license belongs to this machine. Changing its hostname or network cards needs a new key.

Upgrading: run the install script from the newer bundle (Windows: tiqr_setup.exe). Data, settings and the
license stay. The Windows wizard is the exception for tiqr_brand.jsonc: it replaces that file with its answers
and keeps the old one as tiqr_brand.jsonc.bak.
